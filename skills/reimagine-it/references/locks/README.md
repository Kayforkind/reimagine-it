# Design-DNA lock system

A lock captures the design language of a **specific shipped output** and saves it as a reusable pack. Later runs of `/reimagine-it` can apply that pack to a new target — the same medium (webpage → webpage) or a different medium (webpage → slides, PDF → document).

## Syntax

```
/reimagine-it lock <path> [as <name>]     # capture
/reimagine-it lock <path> --unnamed        # capture with an autogenerated name (yyyy-mm-dd-slug)
/reimagine-it <target> --ref <name>        # apply a locked pack
/reimagine-it --list-refs                  # print available locks in the console + a link to this folder
/reimagine-it forget <name>                # remove a lock
```

`<path>` can be a local `.html`, `.pdf`, `.pptx`, `.docx`, `.svg`, or `.md` file. The skill parses what it can and asks about what it cannot (e.g. font stack from a rendered PDF).

## What a lock file contains

Each lock is a markdown pack in this folder (or the host's configured locks folder — see `--host-locks-path` in `local.md`). It looks like a domain pack:

```markdown
# Lock: <name>

Source: <path> (captured <yyyy-mm-dd>)
Extracted by: /reimagine-it lock v2.0

## Palette
- --primary #.....  (frequency: X% of pixels)
- --ink     #.....
- --accent  #.....
- --panel   #.....
- --dim     #.....

## Type stack
- Display: "family, fallback, generic"
- Body:    "family, fallback, generic"
- Meta:    "family, fallback, generic"

## Motifs (recurring shapes / patterns)
- <motif 1>: <where it appears>
- <motif 2>: ...

## Motion signatures
- Persistent: <description>
- Active: <description>
- Narrative: <description>

## 3D signatures
- <element>: <transform> + <shadow>

## Section structure
1. <name> — <purpose>
2. <name> — <purpose>
...

## Voice notes
<one paragraph on tone: "italic serif, monospace kicker, coral for stress; the & does the work">

## Cross-medium translation table (optional)
| Element | webpage → slides | webpage → pdf | webpage → document |
|---------|------------------|---------------|--------------------|
| Display type | Slide title 44pt | Cover title 36pt | H1 32pt |
| Motif | ... | ... | ... |
```

## How extraction works

For **HTML**: parse the CSS variables, count color frequency in the rendered pixel buffer, extract font-family declarations, list `@keyframes` and their targets, enumerate 3D transforms.

For **PDF**: use pdfplumber / pdfminer to extract font names + sizes; render a page to PNG and sample colors; find repeated glyph shapes as motifs.

For **DOCX**: parse `document.xml`, extract used styles, count runs by style.

For **PPTX**: use python-pptx to enumerate theme colors, slide masters, layouts.

Missing signals become explicit questions in the lock file (e.g. `Motion signatures: (source is static; specify or leave blank)`).

## Sharing locks

- Committed locks under `references/locks/*.md` travel with the skill install.
- Personal locks can live in `~/.reimagine-it/locks/` — configured via `local.md` (`user-locks-path`).
- A lock is portable text; share via gist, repo, or email.

## Naming rules

- lowercase, kebab-case, no whitespace
- prefix with `house-` for house style, `client-<name>-` for client style, `demo-` for demo styles

Examples: `house-cinema`, `client-acme-print`, `demo-portfolio-warm`.

## When to lock

- After running `/reimagine-it` and liking the result — save the DNA before the memory of it fades.
- Before shipping a real client site — lock the approved comp so subsequent pages match.
- When you find a page in the wild you like — save it as a reference, iterate on it.

## When not to lock

- One-off experiments (they should stay in `reimagined/` and die there).
- Any output that used a paid API you cannot rerun.
- Any output whose license disallows derivative reuse.
